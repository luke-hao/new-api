# API 密钥的个人 Auto 顺序

在“API 密钥”中主动选择 **Auto · 自动分组**，添加有权限的文字或生图分组，使用上移／下移排列优先级。文字与生图共用该密钥的一份顺序，每次请求只选择支持请求模型的分组。每把密钥独立保存顺序；默认主题支持创建、编辑、行内配置和批量改组，Classic 支持创建与编辑。新建密钥的跨分组重试默认开启。

## 接口与兼容

- Token 的 `auto_groups` 是有序字符串数组，数据库列为 TEXT，Redis 同步保存。创建、读取、编辑和 `PUT /api/token/batch/group` 使用同一字段。
- `/api/user/self/groups` 为每个分组返回 `auto_eligible` 和 `auto_types`（`text`、`image`）；倍率为当前用户实际倍率。显式个人列表至少一项，拒绝重复、无权限和无文字／生图候选的分组。
- 旧 Token 空列表继续使用管理员 Auto 顺序。旧客户端省略字段时保留已有列表；切回固定组也保留个人列表。个人列表失效后请求跳过失效项，全部失效时明确报错，绝不回退全站顺序。

## 调度与计费

每次新请求从个人列表顶部查找支持原始请求模型的组，组内保留既有优先级、权重与稳定调度。初始预选不消耗调用机会。关闭跨组重试后只在首个选定组内重试；开启后按既有可重试错误规则依次尝试列表中的后续组。流式内容已输出、已确认可计费用量和客户端取消仍遵守原有停止重试规则。

会话复用只应用于此次优先选中组内的可用渠道。文字请求与图片生成／编辑请求分别校验模型和端点；Gemini 生图模型也支持其文字协议生图端点。视频、音频、嵌入及重排仍不进入个人 Auto；模型列表还与密钥模型限制相交。Messages 文字计数使用同一初始分流。生图重试切组后重算分组专属价格，并校验原生 4K 分组限制。结算倍率、用户专属倍率和用量日志使用实际选中组；Auto 本身显示“按实际分组计费”。

## 验证与回滚

`controller/token_auto_groups_test.go` 覆盖排序、模型跳组、重试开关、权限撤销、亲和性、倍率、CRUD／批量兼容和存储缓存。可指定独立测试数据库：
`TEST_AUTO_POSTGRES_DSN`、`TEST_AUTO_REDIS_ADDR`。绝不指向生产数据库。

`web/default/scripts/test-auto-groups.mjs` 使用模拟 API 验证两套已构建主题的桌面与手机操作；需 Playwright、`AUTO_QA_OUTPUT/status.json`，输出截图和报告。

旧镜像忽略个人列表，因此回滚必须先停止应用，记录并停用所有带个人列表的 Auto 密钥，再切换旧镜像；重新上线新版健康后，仅恢复仍保持相同列表的已记录状态，保留新增列和数据。部署记录内的 `rollback.sh`、`reapply.sh` 与 `token-rollback-guard.py` 实现此流程。当前实例未使用 Redis；如后续启用，回滚守卫会要求先增加定向缓存失效处理。
